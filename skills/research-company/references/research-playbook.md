# 检索、机会判断与证据

## 1. 身份和业务

核查首页、About、Contact、法律声明、产品目录和服务页。区分品牌、法人与集团/分公司。记录地区、服务范围和日期。

角色判断允许同时存在多个角色：

| 角色 | 寻找的证据 | 不能直接推导的结论 |
| --- | --- | --- |
| 硬件设计/OEM | 自有产品文档、设计声明、固件/硬件开发资料 | 自有品牌等于拥有工厂 |
| 制造/代工/ODM | 工厂能力、生产服务、制造流程、公开制造记录 | 官方说“产品”就等于自产 |
| 系统集成商 | 第三方设备接入、部署、协议桥接、项目交付 | 集成商一定采购裸射频模组 |
| 行业方案商 | 行业方案、端到端交付、项目案例 | 方案页意味着案例已部署 |
| 分销/零售 | 多品牌目录、授权分销声明、销售渠道 | 销售 LoRa 设备等于自主开发 LoRa 设备 |
| 软件/平台 | 平台功能、设备接入、API、合作硬件 | 有平台就需要定制硬件 |
| 原料/器件供应商 | 材料/元器件品类、加工能力、下游用途 | “工业”一词就是气象站客群 |
| 最终用户/运营方 | 业务设施、公开招标、监测/运维需求 | 行业相近就已经有采购计划 |

输出生态位置：上游投入 → 本公司的可控环节与交付 → 下游客户/场景。标明其中的事实与推断。

## 2. 产品和技术

对最相关的具体产品或项目逐项核查：

- 产品名/型号、是否仍在售/仅原型/宣布开发/已停产。
- 功能和被测对象，不能只写“物联网产品”。
- 有线/无线协议和接口、电源、现场部署形态。
- 自有设计、现成设备集成或代理销售的证据。
- 通信替代/新增传感/数据采集的真实位置。
- 目标行业、设施和公开案例。

优先搜索模式：

```text
<公司/域名> about products solutions
site:<官方域名> <产品名> datasheet manual pdf
site:<官方域名> case study deployment project
site:<官方域名> LoRa LoRaWAN RS485 SDI-12 gateway
<公司> partnership new product distributor tender
```

结合公司所在地语言搜索；采用产品名、当地行业术语和案例标题扩展。搜索摘要中的词不能作为型号采用协议的最终证据。

## 3. 产品匹配

每个建议必须形成链条：

**客户具体产品/项目 → 已知场景需求 → 已核查约束 → 我方候选 → 为什么可能适配 → 哪条信息仍需确认。**

无线模块提供射频通信或结合特定 MCU 的处理能力，不能直接测量土壤、雨量、倾斜、液位或气体。传感器完成测量；采集器处理接口和上报；网关承担网络接入；平台实现数据展示或业务逻辑。

不得把 LoRa 等同于 LoRaWAN；不得把射频芯片支持的协议等同于某个模组出厂固件或认证支持。为客户现有产品增添功能通常涉及重新设计，归入新品/改型机会。量产型号已在售并不意味着能直接改装或替换。

技术检查按证据与选型相关性展开：地区频段、协议栈、固件/API、接口/电平、电源、功耗、天线、尺寸、输出功率、法规/认证、工作环境、测量项目与精度。不需要每次把所有参数变成冗长清单。未核查的项写待确认。

先用 1–3 个最强建议说明机会。找不到匹配时写“目前证据不足以推荐具体型号”，给出最有价值的验证问题，不强行推荐 Seeed 产品。

## 4. 合作类型与优先级

| 合作类型 | 典型线索 | 建议询问 |
| --- | --- | --- |
| 现有产品采购/替代供应 | 明确器件类别、持续销售或制造、BOM/接口需求 | 是否自行选型该部件，是否评估额外供应来源 |
| 新品开发/原型验证 | 官方新产品公告、开发项目、公开研发方向 | 是否在评估该通信/测量路线，样品验证什么指标 |
| 项目扩展 | 已有部署、测点扩充、环境监测范围增加 | 哪些新增测点/参数需要接入现有系统 |
| 分销/联合方案 | 多品牌渠道、授权分销、平台硬件生态 | 是否考虑该类别，客户最常提出什么选型需求 |

线索仅支持机会假设，不能独立证明采购意向或预算。公开招聘也不能证明某个新品立项。

优先级：

- 高：具体客户产品、明确匹配环节、公开业务方向一致，有可验证的联系入口。
- 中：有具体场景和相邻技术，关键兼容或采购控制权待确认。
- 低：主要基于行业相邻/通用趋势，缺少具体产品或交付证据。

另列证据置信度，高/中/低，说明来源完整性、直接性、时效性与冲突，不与商业优先级混为一谈。

## 5. 同类公司、竞品与渠道扩展

当用户关注同类拓客时，找 3–5 家，按“相同最终产品/相同项目交付/相同客户行业”排序。

每家公司给出官方 URL、共同点证据、不同的生态角色、潜在产品方向及仍需验证的问题。不要把芯片厂、分销商、终端制造商因为都有 LoRa 关键词就认成直接竞争对手。

对已有客户的竞争对手开展联系时，仅使用该公司的公开产品证据。不要在联系草稿透露已有客户的采购、BOM、报价、项目或其他非公开信息，也不要暗示已有客户替其背书。

对竞品供应关系只报告可核查的公开采用/授权合作，不通过芯片外观、商店标签或行业惯例断言品牌供应商。分别判断“可以服务的同行市场”和“当前客户确认的采购需求”。

## 6. 首次联系

使用公开页面的一项具体观察，提一款最相关产品或产品类别，问一个能确定角色/需求的具体问题。

例型：“看到贵司的 <具体产品> 支持 <已验证接口>。我们有 <已核查候选> 可用于 <推断应用>。请问这部分由贵司选型开发，还是集成现成设备？”

优先公开的研发/产品经理、技术采购、渠道负责人或官方联系表单。没有姓名时使用团队称呼，职能推荐标成推断。默认草稿 80–130 个英文单词，只问一个核心问题；不虚构收件人、邮箱、合作关系或优惠，不自动发送。

## 7. 证据规则

| 标签 | 含义 | 交付要求 |
| --- | --- | --- |
| 事实 | 已读取来源明确支持的外部信息 | 紧邻来源，官方自述与独立验证分开 |
| 推断 | 基于事实提出的商业或技术假设 | 写前提、推理与关键验证条件；引用前提来源 |
| 待确认 | 缺资料、访问受限、过时或相互矛盾 | 写缺口及下一步，不编造替代结论 |

证据台账字段：S1、标题、原始 URL、来源类型、发布日期（未标注则留空）、访问日期、支持的结论、可见短摘录、访问状态。摘录只作定位，遵守宿主引用和版权限制。

以产品页/手册支持技术参数，以案例/公告支持部署或动态，以法律声明/登记支持身份。多个重复转载不构成独立证据。发现版本差异时报告适用型号和日期，不平均数值或静默选择有利版本。

网站可证明“页面这样表述”，不能凭其宣传自动保证商业履约、认证有效性或产品可靠性。不存在公开来源时用待确认，不给出没有依据的财务/出货规模。
